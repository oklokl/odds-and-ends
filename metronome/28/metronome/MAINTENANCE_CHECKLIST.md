# E. 필수 회귀 테스트

## 1) 가장 기본

- [ ] 4/4, Unit 4, 60 BPM — 1초 간격
- [ ] 4/4, Unit 4, 120 BPM — 500ms 간격

## 2) 이번 버그 재현용 핵심 테스트

- [ ] 7/8, Unit 8, 120 BPM — 250ms 간격
- [ ] 최소 3분 이상 연속 재생
- [ ] `강-약-약-약-약-약-약`이 기계적으로 일정함
- [ ] 강박 직전 두 박이 갑자기 몰리지 않음
- [ ] `단다다단...` 형태의 버퍼링성 리듬이 생기지 않음

## 3) 부하 테스트

- [ ] 화면을 켠 상태
- [ ] 화면을 끈 상태
- [ ] 앱을 백그라운드로 보낸 상태

- [ ] 플래시 OFF / ON
- [ ] BPM 변경 후 정상 재시작

# F. 수학 확인표

현재 앱의 한 박 간격:

```text
intervalSeconds = 60 / BPM × (4 / Unit)
framesPerBeat   = 48000 × intervalSeconds
```

예시:

| BPM | Unit | 간격 | 48kHz Frames |
|---:|---:|---:|---:|
| 60 | 4 | 1000ms | 48,000 |
| 120 | 4 | 500ms | 24,000 |
| 120 | 8 | 250ms | 12,000 |
| 200 | 8 | 150ms | 7,200 |

`beatsPerMeasure`는 강박이 다시 오는 주기를 정합니다.

예: 7/8, 120 BPM이면 250ms × 7 = 1.75초마다 강박이 반복됩니다.

# H. 특히 하지 말아야 할 "간단해 보이는 해결"

- [ ] Handler delay 숫자를 계속 임의로 +1ms/-1ms 조정하지 않는다.
- [ ] 박이 밀렸다고 다음 박을 짧게 만들어 무조건 따라잡지 않는다.
- [ ] 모든 문제를 `Thread.sleep()` 하나로 해결하려고 하지 않는다.
- [ ] MP3 길이가 짧다는 이유만으로 메트로놈에 충분하다고 판단하지 않는다.
- [ ] 화면 애니메이션이 정확해 보인다는 이유만으로 오디오도 정확하다고 가정하지 않는다.
- [ ] 소리가 겹친다는 이유로 매 박 이전 소리를 강제로 끊어 transient 타이밍 문제를 가리지 않는다.

메트로놈은 "소리가 예쁘게 재생되는 앱"보다 **시간축을 보존하는 오디오 엔진**이라는 점을 우선해야 합니다.

# I. 향후 기능 확장 시 참고

7/8 같은 변박에서는 추후 다음 악센트 패턴 기능을 추가할 수 있습니다.

```text
2+2+3
2+3+2
3+2+2
```

이 기능을 넣더라도 권장 방식은 동일합니다.

- 박마다 실시간 `play()`를 추가하지 말 것
- 한 마디 PCM을 만들 때 각 그룹 첫 박에 중강박 샘플을 배치할 것
- 필요하면 `strong / medium / weak` 세 개의 PCM 샘플을 사용

즉 기능이 늘어나도 **샘플 기반 사전 합성 원칙**은 그대로 유지하는 것이 좋습니다.
